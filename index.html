01 · Running Cadence

사용 센서 · 3-Axis Accelerometer

휴대폰의 3축 가속도 센서는 X, Y, Z 방향의 움직임을 연속적으로 측정합니다. 러닝 중 발이 지면에 닿을 때마다 몸을 통해 짧은 충격이 휴대폰에 전달되고, 앱은 이 반복적인 충격을 걸음 신호로 사용합니다.

a = √(ax² + ay² + az²)

세 축의 값을 하나의 전체 가속도 크기로 합치면 휴대폰 방향이 조금 바뀌어도 충격의 크기 자체를 추적할 수 있습니다.

3-axis acceleration → magnitude → peak detection → step interval → SPM

현재 앱은 일정 크기 이상의 가속도 피크를 걸음 후보로 판단하고, 같은 충격을 중복 계산하지 않도록 한 번 검출한 뒤 약 250 ms 동안 다음 검출을 제한합니다. 최근 약 15초의 걸음 간격을 이용해 평균 주기를 계산한 뒤 분당 걸음 수로 변환합니다.

Cadence = 60,000 / average step interval(ms)

예를 들어 평균 걸음 간격이 400 ms라면 약 150 SPM으로 표시됩니다. 휴대폰은 손, 주머니, 암밴드 등 몸과 함께 움직이는 위치에 있어야 합니다.

02 · Heart Rate / Camera PPG

사용 센서 · Rear Camera + LED Flash

손가락을 후면 카메라 렌즈와 LED 플래시에 동시에 밀착하면 LED 빛이 손가락 조직을 통과합니다. 심장이 뛸 때마다 손가락 내부의 혈액량이 미세하게 달라지고, 이에 따라 카메라로 돌아오는 빛의 세기도 주기적으로 변합니다. 이 광학 신호를 PPG(Photoplethysmography)라고 합니다.

LED → blood-volume change → RGB camera signal → PPG waveform → BPM

앱은 각 카메라 프레임의 Red, Green, Blue 평균 밝기를 읽습니다. 영상이 충분히 밝고 붉은 성분이 높아졌는지를 이용해 손가락이 실제로 카메라를 덮고 있는지도 확인합니다.

PPG(t) = G(t) / [R(t) + G(t) + B(t)]

현재 구현에서는 Green 성분을 전체 RGB 세기로 정규화해 느린 밝기 변화와 자동 노출의 영향을 줄입니다. 카메라 프레임 간격은 완전히 일정하지 않기 때문에 수집된 데이터를 약 30 Hz 간격으로 다시 샘플링하고, 느린 변화 성분을 제거한 뒤 짧은 평활화를 적용합니다.

그 다음 신호를 일정 시간만큼 이동시키며 자기 자신과 얼마나 비슷한지 계산하는 Autocorrelation을 사용해 가장 강한 반복 주기를 찾습니다.

period T → BPM = 60 / T

예를 들어 파형이 약 0.8초마다 반복되면 약 75 bpm입니다. 앱은 대략 45–200 bpm 범위에서 가능한 주기를 찾고, 자기상관 강도를 신호 품질로 사용합니다. 안정적인 BPM 후보가 여러 번 반복되면 중앙값을 사용해 결과를 안정화합니다.

측정은 약 15–20초 진행되며, 이 기능은 운동 참고용입니다. 의료 진단용 측정기가 아닙니다.

03 · Heart Rate Zone Guide

사용 데이터 · Measured BPM + User Age

나이는 심박수 자체를 측정하는 데 필요한 값이 아닙니다. 측정된 BPM을 개인별 운동 강도 범위로 해석할 때 사용합니다.

Estimated HRmax ≈ 220 − age

앱은 예상 최대심박수를 기준으로 중강도와 고강도 구간을 계산합니다.

Moderate ≈ 50–70% HRmax · Vigorous ≈ 70–85% HRmax

측정된 심박수는 REST / LOW, MODERATE, VIGOROUS, VERY HIGH 중 하나로 표시됩니다. 예를 들어 25세라면 예상 최대심박수는 약 195 bpm이며, 중강도는 약 98–137 bpm, 고강도는 약 137–166 bpm입니다.

이 구간은 운동 강도를 이해하기 위한 참고값입니다. 체중 감량은 특정 BPM 하나보다 총 운동량과 전체적인 에너지 섭취·소비 균형의 영향을 함께 받습니다.

04 · Push-Up / Virtual Proximity

사용 센서 · Front Camera

웹 브라우저에서는 스마트폰의 물리적 근접센서를 직접 읽기 어렵기 때문에 전면 카메라를 이용해 가상의 근접센서를 구현합니다. 이 기능은 사람의 신원을 인식하지 않고, 화면 안에서 얼굴의 위치와 크기만 검출합니다.

Front Camera → Face Detection → Face Bounding Box → Near / Far → Reps

얼굴이 카메라에서 멀어지면 얼굴 박스가 작아지고, 가까워지면 커집니다. 앱은 화면 폭 대비 얼굴 박스 폭의 비율을 거리 지표로 사용합니다.

Face Ratio = Face Width / Camera Frame Width

예를 들어 화면 폭이 640 px이고 얼굴 폭이 160 px이면 Face Ratio는 0.25, 즉 약 25%입니다.

사용자는 처음에 팔을 편 자세에서 CALIBRATE UP, 가장 내려간 자세에서 CALIBRATE DOWN을 한 번씩 수행합니다. 두 값 사이에 서로 다른 UP/DOWN 판정선을 두는 히스테리시스를 적용해 경계에서 상태가 빠르게 튀는 현상을 줄입니다.

UP → DOWN → UP = +1 REP

또한 최근 여러 프레임의 얼굴 크기를 함께 사용해 순간적인 얼굴 검출 흔들림을 줄입니다. 얼굴이 한 번 가까워지는 것만으로는 카운트되지 않고, 내려갔다가 다시 올라오는 한 사이클이 완료되어야 1회가 증가합니다.

05 · Calibration

왜 보정이 필요한가?

휴대폰 기종, 전면 카메라 화각, 사용자의 얼굴 크기, 폰과 사람 사이 거리 등이 모두 다르기 때문에 하나의 고정된 얼굴 크기 기준으로 모든 사용자를 판단하면 오차가 커집니다.

그래서 앱은 사용자가 실제 자세에서 UP과 DOWN을 직접 저장하게 하고, 절대적인 얼굴 크기보다 개인별 UP–DOWN 범위 안에서 현재 값이 어디에 있는지를 기준으로 판정합니다.

06 · Local Processing & Privacy

Camera data stays on the device

카메라 영상은 운동 분석을 위해 브라우저 내부에서 처리됩니다. 서버에 영상을 업로드하거나 저장하지 않고, 분석 후 필요한 숫자 데이터만 사용합니다.

러닝 시간, 케이던스, 측정 심박수, 팔굽혀펴기 횟수 등의 기록은 현재 버전에서 브라우저의 Local Storage에 저장됩니다. 따라서 같은 기기와 같은 브라우저에서는 다시 확인할 수 있지만 다른 기기로 자동 동기화되지는 않습니다.
